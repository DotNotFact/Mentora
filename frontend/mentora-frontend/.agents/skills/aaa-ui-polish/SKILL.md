# AAA-уровень UI-полировки

> Администратор явно попросил (2026-08-06): не "сдержанный" минимализм
> из `mentora-design/SKILL.md`, а такая плотность элементов и анимации,
> которая радует глаз и выглядит как полноценный AAA-проект. Референс —
> дисциплина игровых клиентов уровня League of Legends / Genshin Impact /
> Overwatch (не буквальный игровой HUD в LMS — та же ДИСЦИПЛИНА: каждое
> состояние анимировано, ничего не "щёлкает" мгновенно, визуальная
> плотность и физика взаимодействий выше типичного B2B SaaS).
>
> Это НЕ "больше визуального шума". Читаемость/иерархия из
> `mentora-design` (spacing, типографика, radius, палитра индиго/амбер)
> остаются в силе без изменений — AAA-полировка добавляется ПОВЕРХ них.
> AAA здесь значит: богатая анимированная обратная связь + spring-физика
>
> - продуманный ambient-моушен, а не нагромождение элементов без смысла.

## Что этот skill явно переопределяет в mentora-design/SKILL.md

Для экранов/задач, где применяется этот skill (сейчас — schedule/10 и
всё, что от него зависит: 11, 12, 14), следующие пункты
`mentora-design/SKILL.md` ослабляются/заменяются. Всё остальное
(токены цвета, radius-шкала, spacing rhythm, типографическая шкала,
`prefers-reduced-motion` killswitch из schedule/07) — БЕЗ изменений.

| Было (mentora-design)                                                     | Стало (aaa-ui-polish)                                                                                                                                                                               |
| ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Вступительная цитата: "restrained motion"                                 | Выразительный, но управляемый моушен — см. "Принцип 3 фокусов" ниже.                                                                                                                                |
| Elevation: "surface moves at most one level on interaction"               | Ключевые интерактивные элементы (карточки курсов, CTA, progress) могут комбинировать подъём multi-layer: тень + scale + glow одновременно.                                                          |
| "`hover:scale-[1.02]` ... the one component allowed that scale treatment" | Снято — тактильный hover/press (`scale`, `translate-y`, spring easing) допустим на любом кликабельном элементе, не только `CourseCard`.                                                             |
| "Optional glow accent for a single emphasized surface per screen"         | Лимит "один глоу на экран" снят для геймифицированных элементов (progress rings, streak-счётчики, badge/achievement pop-in) — но не превращать КАЖДУЮ карточку в глоу, см. "3 фокуса".              |
| "never animate width/height on lists >10 items"                           | ОСТАЁТСЯ в силе без исключений (перформанс) — плотность моушена не означает layout-thrashing; анимировать `transform`/`opacity`/`filter`, никогда `width`/`height`/`top`/`left`, даже в AAA-режиме. |

## Принцип "3 фокуса"

Плотность ≠ хаос. На любом экране одновременно активно (в процессе
анимации/только что среагировало) не больше **3** элементов сразу —
например: progress ring тикает + одна карточка hover-приподнята + один
CTA с лёгкой pulse-подсветкой. Если анимируется всё разом, глазу не за
что зацепиться, и это снова читается как "плохо", просто в другую
сторону (не "как школьник рисовал", а "аляповато"). Остальные элементы
находятся в состоянии "готов откликнуться при взаимодействии" — не
двигаются самостоятельно в покое, кроме одного-двух тонких
ambient-элементов на экран (см. ниже).

## Конкретные паттерны

- **Числа считают, а не появляются.** Любое крупное число (счётчик
  курсов, XP/прогресс, цена, статистика на дашборде) анимированно
  "тикает" от 0 (или от предыдущего значения) до целевого за 400-800ms
  при монтировании/обновлении — не мгновенная замена текста. Финальное
  значение всегда доступно как обычный текст для скринридеров
  (`aria-live="polite"` на контейнере, не полагаться только на визуал).
- **Progress — заполняется, не появляется готовым.** `ProgressBar`/
  progress ring анимируют заливку от текущего к новому значению
  (`transition-[stroke-dashoffset]`/`transition-[width]` разрешено
  ИМЕННО для одиночного progress-индикатора — не список, поэтому не
  подпадает под запрет "width/height на списках >10").
- **Карточки — tilt + glow + lift на hover**, не только
  `scale-[1.02]` из базового скилла: лёгкий `rotate-[0.5deg]`/
  `translate-y-[-4px]` + переход тени на уровень выше + тонкая
  primary-tinted glow-тень (как в elevation-таблице mentora-design, но
  без лимита "один на экран" для карточек курсов в фокусе).
- **Появление списков — staggered, не разом.** Сетка карточек
  (каталог, "Мои курсы", дашборд) появляется с small stagger (30-60ms
  между элементами, `animate-in fade-in slide-in-from-bottom-2`) —
  ощущение "рассыпающихся по местам" элементов, не резкий swap
  skeleton→content.
- **Достижения/сертификаты — pop-in с отдачей.** Момент получения
  сертификата (schedule/14) или закрытия курса — bounce/spring pop-in
  (`--ease-spring` ниже) значка/карточки, не тихое появление наравне с
  остальным UI. Это единственное место, где допустим
  confetti-подобный ambient-эффект (лёгкий, не блокирующий контент).
- **Активный пункт меню "скользит", а не мигает.** Sidebar/tab
  active-индикатор (schedule/12) — единая полоса/подложка, которая
  плавно перемещается между пунктами (`layoutId`-подобная техника или
  `transform: translateY()` с spring-easing), а не резкая смена
  подсветки на разных DOM-узлах.
- **Ambient-фон — тонкий, максимум 1-2 на экран.** Hero/landing секции
  могут иметь очень медленный (15-30s loop) дрейф градиента/blur-пятна
  на фоне — не более 1 такого элемента на экран, амплитуда минимальна
  (не должно отвлекать от контента, не должно быть замечено при первом
  взгляде, только на "втором чтении").
- **Кнопки — физика нажатия.** `active:scale-[0.97]` + чуть более
  быстрый `duration-100` на press vs `duration-150` на hover — ощущение
  физического отклика, не просто цветовая смена.

## Easing/spring-словарь (закрывает находку про несуществующие `--ease-*`)

Добавить в `@theme` (`globals.css`) при реализации — реальные значения,
не плейсхолдеры из неадаптированных Emil Kowalski skills:

```css
--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1); /* bouncy pop-in: badges, counters, card mount */
--ease-out-expo: cubic-bezier(0.16, 1, 0.3, 1); /* snappy hover/press */
--ease-in-out-smooth: cubic-bezier(0.65, 0, 0.35, 1); /* page/tab transitions */
```

## Где применять в первую очередь (объём schedule/10)

- Дашборд-статистика (`StatCard`) → анимированный count-up + лёгкий
  bounce иконки при монтировании.
- `CourseCard` → расширенный hover (tilt+glow+lift) вместо только
  `scale-[1.02]`.
- Прогресс-бары/кольца прохождения курса → анимированная заливка, не
  статичный `<div>`.
- Sidebar/nav активный пункт (schedule/12) → скользящий индикатор.
- Момент получения сертификата (schedule/14) → spring pop-in +
  локальный confetti-эффект.
- Пустые/loading-состояния → shimmer + staggered skeleton reveal вместо
  плоского fade.

## Guardrails (не подлежат ослаблению)

- `prefers-reduced-motion` по-прежнему выключает ВСЁ это (killswitch из
  schedule/07) — AAA-режим не получает исключения, ни одно.
- Анимировать только `transform`/`opacity`/`filter` (GPU-friendly) —
  никогда `width`/`height`/`top`/`left` в списках/сетках.
- У каждой анимации есть смысл (смена состояния, обратная связь,
  иерархия внимания) — чисто декоративный зацикленный моушен ограничен
  1-2 ambient-элементами на экран, не на каждую карточку.
- Анимированные счётчики/прогресс всё равно отдают финальное значение
  текстом/`aria-live` для скринридеров — не полагаться только на
  визуальную анимацию как источник данных.
