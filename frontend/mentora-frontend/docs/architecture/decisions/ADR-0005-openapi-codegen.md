# ADR-0005: OpenAPI + orval codegen

## Статус

Принято

## Контекст

Бэкенд на C# ASP.NET Core экспортирует Swagger/OpenAPI. Ручное
поддержание TypeScript-типов и клиентов API для 6+ доменов (auth, courses,
enrollments, payments, analytics, media) быстро расходится с реальным
контрактом и создаёт runtime-ошибки, которые strict TypeScript должен был
бы ловить на этапе компиляции.

## Решение

`openapi/openapi.yaml` — единственный источник истины API-контракта на
фронтенде. `orval` генерирует axios-клиент и Zod/TS-типы в
`src/shared/api/generated/` (`yarn api:generate`, конфиг —
`orval.config.ts`, mode: `tags-split`). Сгенерированный код не
редактируется вручную — при необходимости менять поведение запроса,
меняется `override`/шаблон в `orval.config.ts` или сам API-контракт.

## Последствия

- Любое расхождение фронтенда с бэкенд-контрактом обнаруживается на
  `yarn typecheck` сразу после `yarn api:generate`, а не в runtime.
- Новый эндпоинт бэкенда становится доступен фронтенду только после
  обновления `openapi.yaml` — это осознанное узкое место, гарантирующее,
  что контракт документирован до использования.
- Требует, чтобы `openapi.yaml` синхронизировался вручную с реальным
  Swagger бэкенда до тех пор, пока не настроена автоматическая
  синхронизация (см. `openapi/README.md`).
