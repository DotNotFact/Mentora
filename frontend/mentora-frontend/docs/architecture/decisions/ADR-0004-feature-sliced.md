# ADR-0004: Feature-модули + разделение server/UI-state

## Статус

Принято

## Контекст

При росте LMS-платформы (auth, каталог, редактор курсов, обучение,
оплата, аналитика) плоская структура `components/`+`hooks/` быстро
превращается в свалку с неявными зависимостями между несвязанными
экранами. Нужны явные границы модулей и однозначное правило, где живёт
какое состояние.

## Решение

1. **Feature-модули** (`src/features/<name>/`): `components/`, `hooks/`,
   `store.ts`, `schemas.ts`. Фича не импортирует другую фичу напрямую —
   переиспользуемое выносится в `src/shared/`.
2. **Разделение состояния**:
   - Server-state (данные с бэкенда) — исключительно TanStack Query,
     живёт в `features/*/hooks/`.
   - UI-state (модалки, фильтры до применения, drag-состояние,
     позиция плеера) — исключительно Zustand, в `features/*/store.ts`.
   - Запрещено дублировать server-state в Zustand — источник истины один.
3. Роуты (`src/app/routes/`) — тонкий слой композиции, не содержат
   бизнес-логику и не создают собственный стейт сверх параметров
   маршрута.

## Последствия

- Новую фичу можно понять, читая только её собственную папку + `shared/`.
- Явное правило "server-state только в Query" убирает целый класс багов
  рассинхронизации кэша и локального состояния.
- Требует дисциплины при код-ревью (см. `.agents/skills/review/SKILL.md`,
  пункты про cross-feature импорты и дублирование server-state).
