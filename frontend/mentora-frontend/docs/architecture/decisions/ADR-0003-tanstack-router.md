# ADR-0003: TanStack Router

## Статус

Принято

## Контекст

Нужен роутинг с полной типобезопасностью параметров маршрута (например,
`courseId` в `/courses/$courseId`) и поддержкой файловой организации
роутов, соответствующей структуре `src/app/routes/`.

## Альтернативы

- **React Router** — более распространён, но типобезопасность параметров
  и loader'ов слабее без дополнительной обвязки.
- **Next.js App Router** — потребовал бы полного перехода на Next.js
  (SSR/RSC), что избыточно для SPA-фронтенда, живущего в монорепозитории
  рядом с отдельным бэкендом на C#.

## Решение

TanStack Router с файловыми роутами в `src/app/routes/`. Дерево роутов
собирается в `src/app/router.tsx` (реализуется в schedule/00). Защищённые
роуты оборачиваются `AuthGuard` (schedule/01), а не проверяются вручную в
каждом компоненте страницы.

## Последствия

- `courseId`, `moduleId` и подобные параметры типизированы end-to-end.
- Роуты остаются тонкими (правило CLAUDE.md #21) — бизнес-логика живёт в
  `features/*`, роут только импортирует и передаёт параметры.
- Экосистема меньше, чем у React Router — при выборе сторонних
  роутинг-аддонов проверять совместимость заранее.
