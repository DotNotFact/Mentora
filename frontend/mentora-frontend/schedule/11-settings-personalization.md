# 11 — Settings & Personalization (тема по умолчанию — тёмная)

Статус: [x] выполнена

## Контекст

Администратор (2026-08-05) явно попросил добавить задачу: раздел
"Персонализация" в настройках, тёмная тема по умолчанию (не светлая, как
сейчас), несколько готовых цветовых тем (тёмная + зелёный/красный/
фиолетовый/и т.д. акцент), и возможность пользователю самому собрать
свою цветовую схему из предложенных вариантов.

## Цель

Пользователь (любая роль) может зайти в "Настройки → Персонализация",
выбрать одну из готовых тем (включает минимум: тёмная-индиго (по
умолчанию), тёмная-зелёная, тёмная-красная, тёмная-фиолетовая,
светлая-индиго — исходная палитра Mentora как один из вариантов, не
единственный) или переключить светлый/тёмный режим независимо от
акцентного цвета. Выбор сохраняется между сессиями (для гостя —
локально в браузере; для аутентифицированного пользователя — было бы
логично синхронизировать на бэкенде, но бэкенда с полем
`preferences`/`theme` у пользователя пока нет — см. "Отклонения" по
факту реализации и "Не входит").

## Ветка

`feature/11-settings-personalization`

## Шаги

1. **Токенизация под тему.** Текущие CSS-переменные в
   `src/styles/globals.css` (`@theme` блок) — фиксированные hex-значения.
   Переработать под CSS custom properties на `:root`/`[data-theme=...]`
   селекторах (паттерн, который уже используют Artifacts в этой среде —
   `:root[data-theme="dark"]`), чтобы Tailwind-утилиты (`bg-background`,
   `text-foreground` и т.д.) продолжали резолвиться из тех же
   `--color-*` имён, но их ЗНАЧЕНИЯ менялись по теме, а не только сам
   набор классов.
2. **Набор готовых тем.** Минимум 5 (см. "Цель"). Каждая тема — полный
   набор `--color-background/foreground/card/border/primary/accent/
success/destructive/muted/...` — не только "поменять primary", у тёмных
   тем меняется вся поверхность (background/card/border/foreground
   тоже, не только акцент). Определить структуру данных для темы (id,
   название, light/dark, значения токенов) — вероятно
   `shared/config/themes.ts`.
3. **Хранение выбора.** Zustand store с `persist` (паттерн уже есть в
   `features/auth/store.ts`) — например `shared/config/theme-store.ts`
   или `features/settings/store.ts` (создать feature `settings`, если
   ещё не создан — проверить `src/features/` на момент реализации).
   Дефолт при первом визите — тёмная-индиго (НЕ светлая, вопреки
   нынешнему поведению).
4. **UI переключения.** Страница/секция "Настройки → Персонализация"
   (новый роут, например `/settings/personalization`, доступен любой
   аутентифицированной роли — уточнить у администратора, должна ли быть
   доступна и гостю, если schedule/13-roles-and-collaboration.md к
   этому моменту уже определит гостевую роль). Превью каждой темы
   (мини-свотчи/карточка-пример), явный переключатель светлый/тёмный
   независимо от акцента, если это не противоречит выбранной готовой
   теме. Переключение темы анимировать плавным cross-fade значений
   CSS-переменных (`transition` на `background-color`/`color`/`border-
color`, easing — `--ease-in-out-smooth` из
   `.agents/skills/aaa-ui-polish/SKILL.md`, если задача 10 уже завела
   этот токен, иначе временный эквивалентный cubic-bezier), а не
   мгновенный "щелчок" — сама смена темы такой же значимый момент
   обратной связи, как и остальные интеракции.
5. Применить тему максимально рано (до первого рендера/до FOUC) —
   аналогично тому, как artifact-рантайм в этой среде уже проставляет
   `data-theme` на `<html>` до пейнта; на практике — читать сохранённое
   значение синхронно в `index.html`/самом начале `main.tsx`, не после
   монтирования React-дерева, иначе будет заметная вспышка светлой темы
   при загрузке.
6. Прогнать ключевые экраны (см. список в schedule/07 → "Отклонения")
   в тёмном режиме на предмет читаемости/контраста — тени/border,
   рассчитанные на светлый фон (`shadow-sm` на белой карточке), могут
   не работать так же на тёмной поверхности.

## Дизайн-заметки

Тёмная тема — не инверсия светлой в лоб. Использовать признанный подход
(тёмно-серые/тёмно-синие поверхности с приподнятыми элементами чуть
светлее фона, не чёрный #000000) — согласовать конкретные hex-значения
с `.agents/skills/mentora-design/SKILL.md` при реализации (добавить
туда раздел "Themes", если такого ещё нет к моменту старта).

## Критерии готовности

- Новый пользователь/гость при первом визите видит тёмную тему без
  дополнительных действий.
- Минимум 5 готовых тем, переключение мгновенное, без перезагрузки
  страницы.
- Выбор переживает обновление страницы и новый визит (persist).
- Ни одна тема не даёт объективно нечитаемый контраст текста на фоне
  (проверить хотя бы базово, WCAG AA — 4.5:1 для обычного текста).
- `yarn verify` зелёный, скриншот-гейт для тёмной темы по ключевым
  экранам.

## Не входит

Синхронизация темы с бэкендом/между устройствами пользователя (нужно
поле в модели User на бэкенде, которого пока нет — см. `openapi.yaml`);
полностью произвольный color-picker (RGB/HEX на выбор пользователя) —
только заранее подготовленные темы, как явно попросил администратор.

## Отклонения от исходного плана (осознанные, по факту реализации)

- **UI переключения — карточка темы = сам переключатель, без
  отдельного light/dark-тумблера.** Шаг 4 упоминал "явный переключатель
  светлый/тёмный независимо от акцента, если это не противоречит
  выбранной готовой теме" — но с фиксированным набором 5 тем (4 тёмных
  + 1 светлая, не 4+4 симметрично) независимый тумблер был бы
  рассинхронизирован с реально доступными пресетами (например, что
  показывать при "светлый" + "зелёный", если `light-green` не
  существует?). Каждая из 5 карточек — сама целиком клик-переключатель;
  это проще и не вводит несуществующие комбинации. Расширение до
  полного набора light+dark × 4 акцента — возможное будущее развитие,
  не в объёме этой задачи.
- **Реальный баг, найденный и исправленный по ходу (не в исходных
  находках): `src/styles/globals.css` содержал сломанный CSS-комментарий
  с 2026-08-06** — комментарий про `prefers-reduced-motion` (добавлен в
  schedule/07) содержал буквальную последовательность `*/` в середине
  текста ("transition-\*/animate-in-\*"), что преждевременно закрывало
  комментарий; `yarn format` в рамках schedule/10 переформатировал
  "вылившийся" из комментария текст в мусорные CSS-конструкции. Браузеры
  молча игнорировали невалидные top-level токены (визуально ничего не
  ломалось, `yarn verify`/build проходили), поэтому баг не был замечен
  раньше. Исправлено при переписывании файла под темизацию.
- **Реальный баг, найденный администратором в процессе ревью
  (2026-08-06): нативные спиннер-стрелки `<input type="number">`
  ("Цена от"/"Цена до" в фильтрах каталога) рендерились с белым OS-фоном
  поверх тёмной темы** — браузерный chrome для number-инпутов не
  наследует CSS-токены темы. Убраны полностью (`appearance: textfield`
  + `::-webkit-*-spin-button { appearance: none }` в `globals.css`) —
  единственный кросс-браузерно надёжный способ, перекрасить их под тему
  штатными средствами CSS невозможно.
- **`meta[name="theme-color"]`** обновлён с `#6366f1` на `#020617` —
  соответствует новому дефолтному (тёмному) фону, иначе мобильный
  browser chrome не совпадал бы с реальным фоном страницы при первой
  загрузке.
- **Проверка контраста (WCAG AA) — расчётная, не через инструмент.**
  Посчитаны коэффициенты для самых нагруженных пар: `muted-foreground`
  на `card` ≈ 6.96:1, `muted-foreground` на `background` ≈ 7.87:1,
  `primary` (как текст/ссылка) на `background` ≈ 4.52:1 — все проходят
  порог 4.5:1 для обычного текста (последняя пара — впритык, но
  проходит). Не прогонялось через автоматизированный audit-инструмент
  (Lighthouse/axe) — "хотя бы базово", как и просил сам шаг 6.
- **`mentora-design/SKILL.md`** получил новый раздел "Themes" и таблицы
  цветов обновлены с исходных светлых значений на `dark-indigo`
  (текущий дефолт) — задокументировано в самом skill-файле, что было
  показано историческую светлую палитру.
- **Минимальная ссылка "Персонализация" в `header.tsx`**, не входила в
  шаги задачи явно — без неё новая страница была бы недостижима
  (`schedule/12-dashboard-shell-navigation.md`, ещё не выполнена,
  заменит `Header` на полноценную навигацию и унаследует эту ссылку).
