# Schedule — пошаговый план реализации Mentora

## Режим работы — ВАЖНО

Ни одна задача не начинается автоматически. Агент реализует задачу ТОЛЬКО
после явной команды администратора вида "выполни schedule/NN". Прочитать
и понять план можно в любой момент — начинать писать код нельзя без команды.

## Как это работает (после команды администратора)

Полный процесс, включая скриншот-QA гейт и параллельный запуск задач —
в `AGENTS.md` → "Schedule-driven development", "Параллелизация задач",
"Скриншот-QA гейт". Кратко:

1. Прочитать эту страницу и файл конкретной задачи
2. Обновить .agents/STATE.md → IN_PROGRESS: NN
3. `git checkout -b feature/<slug> main` в изолированном git worktree
   (репозиторий — монорепо `DotNotFact/Mentora`, рабочая директория —
   `frontend/mentora-frontend/`)
4. Выполнить шаги, после каждого — typecheck + lint
5. Для UI-задач — обязательный скриншот-гейт (375/768/1280px,
   `docs/qa-screenshots/`) до отметки готовности
6. Статус задачи в файле → [x], коммит на русском (`git`)
7. `git push` → `gh pr create --fill` (тело PR — со скриншотами)
8. `yarn verify` зелёный → `gh pr merge --squash --delete-branch`
   автоматически (дефолтная политика, без доп. подтверждения на каждый
   мерж)
9. .agents/STATE.md → AWAITING_ADMIN_COMMAND
10. Остановиться и ждать следующей команды

`git` — для коммитов/веток, `gh` — для PR/CI. Один не заменяет другой.

## Статусы задач

[ ] не начата · [~] в процессе · [x] выполнена

## Порядок и параллелизация

`00-verify-setup` и `01-auth` — строго последовательно первыми (на них
завязано почти всё остальное). После них независимые фичи
(`02`, `03`, `06`) можно поручить параллельным изолированным агентам —
см. AGENTS.md → "Параллелизация задач". В любом случае: каждая задача
стартует только по отдельной явной команде администратора — порядковый
номер не даёт разрешения начинать без спроса.

## Пополнение бэклога — задачи не должны заканчиваться

Когда все задачи ниже выполнены (или в процессе работы над одной из них
находится осмысленная новая идея, не покрытая ни одной существующей
задачей) — агент обязан САМ добавить новый файл `schedule/NN-slug.md` по
тому же шаблону, что и остальные задачи (Цель / Ветка / Шаги /
Дизайн-заметки / Критерии готовности / Не входит / Коммит), и добавить
ссылку на него в "Список задач" ниже — вместо того чтобы просто
остановиться в `AWAITING_ADMIN_COMMAND` с пустым бэклогом.

Это касается ТОЛЬКО добавления задачи в план (Режим A — планирование, как
и весь `schedule/`). Реализация новой задачи по-прежнему требует
отдельной явной команды администратора, как и любая другая задача из
этого списка (см. "Режим работы — ВАЖНО" выше) — сам факт появления
файла `schedule/NN-slug.md` НЕ авторизует его выполнение.

Источники идей для новых задач:

- Пробелы и заметки, оставленные в секциях "Отклонения от исходного
  плана" уже выполненных задач — там часто явно отмечены кандидаты
  ("хорошая цель для отдельной задачи", "не входит в эту задачу, но...").
- Функциональность, которая есть практически у любой LMS-платформы, но
  которой пока нет у Mentora (отзывы/рейтинги — задача 17, поиск —
  задача 15, уведомления — задача 16, обсуждения/Q&A под уроком —
  задача 19, публичный профиль инструктора — задача 20).
- Функциональность, которая выделяет Mentora на фоне конкурентов —
  не "как у всех", а то, чего нет у типичных LMS (Coursera, Udemy,
  Skillbox и т.п.) — например геймификация (streaks/XP/бейджи, задача
  18). Отдавай предпочтение конкретным, проверяемым идеям перед общими
  формулировками вида "улучшить UX".

Полный аудит проекта (2026-08-06, по явному запросу администратора)
добавил задачи 15-20 — см. "Список задач" ниже. Дополнительные идеи,
найденные при том же аудите, но НЕ оформленные в отдельные задачи
(осознанно — либо неясная продуктовая ценность прямо сейчас, либо
слишком большой охват для одной задачи, либо зависят от бизнес-решения
вне компетенции агента):

- **i18n/мультиязычность** — весь UI сейчас захардкожен на русском без
  какой-либо инфраструктуры интернационализации; учитывая, что вся
  документация проекта и коммуникация с администратором тоже на
  русском, неочевидно, что это реальный сейчас приоритет — заводить
  задачу только по явному запросу.
- **Купоны/промокоды на checkout** — требует продуктового решения о
  модели скидок (проценты? фикс? временные акции?) прежде чем писать
  шаги реализации.
- **Wishlist/избранное** — небольшая, дешёвая в реализации фича
  (сохранить курс "на потом"), кандидат для быстрой будущей задачи.
- **SEO-инфраструктура** (sitemap.xml, structured data/JSON-LD для
  курсов) — реальный пробел (проверено при аудите — ни sitemap, ни
  robots.txt не генерируются), но ниже по пользовательской видимости,
  чем задачи 15-20.
- **Живые сессии/вебинары, лидерборды, AI-рекомендации курсов** — более
  амбициозные идеи, требуют либо реального бэкенда, либо продуктового
  решения о scope — не оформлены как задачи, чтобы не плодить
  неактуальные заглушки.
