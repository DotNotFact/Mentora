# 16 — Уведомления (toast + центр уведомлений)

Статус: [ ] не начата

## Контекст

Полный аудит проекта (2026-08-06). Найдено: в проекте нет ни одной
toast-библиотеки — успешные/неуспешные действия (вход, оплата, запись
на курс) сообщаются только инлайн-текстом внутри формы, если вообще
сообщаются. Нет и персистентного центра уведомлений — события вроде
"вас пригласили в группу" (`schedule/13`) или "получен сертификат"
(`schedule/14`) некуда показать, если пользователь не находится на
той же странице в момент события.

## Цель

Два связанных, но разных механизма:

1. **Toast** (эфемерные, для мгновенной обратной связи на действие) —
   "Курс сохранён", "Не удалось оплатить", "Отзыв опубликован".
2. **Центр уведомлений** (персистентный, колокольчик в `TopBar` со
   счётчиком непрочитанных) — для событий, которые могли произойти не
   на текущем экране: приглашение в группу, получение сертификата,
   новый урок в курсе, на который записан.

## Ветка

`feature/16-notifications`

## Шаги

1. Добавить shadcn `sonner` (`npx shadcn@latest add sonner`), смонтировать
   `<Toaster />` один раз в `AppProvider`.
2. Завести `shared/lib/toast.ts` — тонкая обёртка (`toast.success`/
   `toast.error`) поверх sonner, чтобы не импортировать библиотеку
   напрямую в каждом месте (единая точка, если библиотека сменится).
3. Подключить toast к существующим мутациям, которые сейчас показывают
   только инлайн-ошибку: `use-login`, `use-register`, `use-save-course`,
   `use-enroll`, `use-create-checkout` — успех/ошибка через toast
   ДОПОЛНИТЕЛЬНО к существующим инлайн-состояниям формы (не вместо —
   инлайн-ошибка на поле остаётся для валидации, toast — для
   результата всего действия).
4. `openapi.yaml`: добавить `Notification` (id, userId, type, title,
   body, link, read, createdAt), `GET /notifications`,
   `POST /notifications/{id}/read`. Перегенерировать клиент.
5. `features/notifications/` — `useNotifications` (TanStack Query,
   поллинг раз в 60с — реального push нет), `NotificationBell` (иконка
   в `TopBar` с бейджем непрочитанных, см. схему count-up из
   `aaa-ui-polish` для анимации числа), `NotificationList` (dropdown/
   popover с последними уведомлениями, клик — отметить прочитанным +
   перейти по `link`).
6. Реальные точки триггера (мок-бэкенд): успешная запись в группу
   (schedule/13, когда будет реализована), получение сертификата
   (schedule/14, когда будет реализована) — если эти задачи ещё не
   выполнены на момент реализации 16, завести уведомление минимум для
   уже существующих событий (успешная запись на курс, успешная оплата)
   и оставить `TODO`-комментарий с точкой расширения для 13/14.
7. Скриншот-гейт: открытый dropdown с уведомлениями + toast в моменте
   показа, 375/768/1280px.

## Дизайн-заметки

Toast — `animate-in slide-in-from-bottom-2` (или sonner-дефолт, если
он уже соответствует духу `aaa-ui-polish`). `NotificationBell`
непрочитанный бейдж — animated count-up при увеличении числа
(переиспользовать `useCountUp` из `shared/hooks/use-count-up.ts`,
schedule/10).

## Критерии готовности

- Toast появляется и автоматически исчезает для каждой из
  перечисленных в шаге 3 мутаций (успех и ошибка).
- Колокольчик показывает точное число непрочитанных, обновляется без
  перезагрузки страницы (поллинг).
- Клик по уведомлению отмечает его прочитанным и переходит по ссылке.
- `role="status"`/`aria-live` для toast — скринридер объявляет
  появление.

## Не входит

Push-уведомления браузера (Notification API), email-дайджесты,
реальная доставка через WebSocket/SSE (только поллинг — бэкенда для
push нет).
