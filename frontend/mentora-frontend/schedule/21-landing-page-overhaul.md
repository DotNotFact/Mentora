# 21 — Лендинг: главная страница как полноценная маркетинговая витрина

Статус: [ ] не начата

## Контекст

Полный аудит проекта (2026-08-06, по явному запросу администратора
проанализировать проект целиком и добавить задачи, чтобы опережать
своё время). Найдено: `src/app/routes/index.tsx` — заголовок "Mentora"
и сетка популярных курсов, больше ничего. Ни подзаголовка/оффера, ни
CTA-кнопки, ни единого элемента социального доказательства
(цифры/отзывы), ни объяснения "почему Mentora" для нового посетителя,
который ещё не знает продукт. Это первая страница, которую видит
гость — сейчас она не продаёт продукт вообще.

## Цель

Главная страница — полноценная маркетинговая витрина с популярными
паттернами современных SaaS/EdTech-лендингов (Coursera, Udemy, Linear,
Vercel — везде один и тот же проверенный набор блоков):

1. **Hero** — заголовок + подзаголовок-оффер + основной CTA
   ("Смотреть каталог" → `/courses`) + вторичный CTA (гостю —
   "Зарегистрироваться", вошедшему — "Мои курсы").
2. **Статистика/социальное доказательство** — 3-4 крупных числа
   (курсов, студентов, инструкторов, средний рейтинг — если
   `schedule/17` уже выполнена) с animated count-up при попадании в
   viewport (`useCountUp`, `shared/hooks/use-count-up.ts`, schedule/10).
3. **Популярные курсы** — уже есть (`PopularCourses`), оставить, но
   переместить/оформить как секцию с заголовком, не голым списком
   сразу под H1.
4. **"Почему Mentora"** — 3-4 карточки с иконкой + коротким текстом
   (практикующие инструкторы, сертификаты — `schedule/14`, гибкий темп,
   сообщество — `schedule/19`, если выполнена).
5. **FAQ** — аккордеон (shadcn `accordion`) с 4-6 частыми вопросами.
6. **Финальный CTA** — крупный блок "Начните учиться сегодня" перед
   футером, повтор основного призыва к действию для тех, кто долистал
   до конца, не кликнув раньше.

## Шаги

1. `features/marketing/` (новый feature-модуль — контент лендинга не
   принадлежит `courses`) — секции как отдельные компоненты: `Hero`,
   `StatsSection`, `WhySection`, `FaqSection`, `FinalCta`.
2. `Hero` — заголовок/подзаголовок (копирайт — конкретный, не
   абстрактный "лучшая платформа"), два CTA (`Button` primary +
   outline), опциональный тонкий ambient-фон
   (`aaa-ui-polish` → "Ambient-фон", максимум 1 на экран, амплитуда
   минимальна).
3. `StatsSection` — 3-4 `StatCard`-подобных блока (переиспользовать
   визуальный паттерн `features/analytics/components/stat-card.tsx`,
   не сам компонент — тот завязан на dashboard-специфичные пропсы),
   count-up запускается при пересечении viewport
   (`IntersectionObserver`, паттерн уже есть в `course-grid.tsx` для
   infinite scroll — переиспользовать идиому, не копировать код 1:1).
4. `WhySection` — сетка карточек, `Card` + иконка (lucide) + заголовок
   + текст, staggered reveal (`aaa-ui-polish`).
5. `FaqSection` — shadcn `accordion` (`npx shadcn@latest add
accordion`), 4-6 вопросов.
6. `FinalCta` — секция с фоном `bg-primary`/`bg-secondary` (акцент,
   отличный от остального фона страницы), крупный CTA.
7. `routes/index.tsx` — собрать секции по порядку, `useDocumentMeta`
   остаётся.
8. Скриншот-гейт: полная страница (все секции), 375/768/1280px.

## Дизайн-заметки

Это ПЕРВАЯ страница гостя — держать плотность по правилу "3 фокуса"
(`aaa-ui-polish`) особенно строго, здесь легче всего скатиться в
"аляповато" при попытке впечатлить. Статистика "должна быть настоящей"
хотя бы правдоподобно (не "1,000,000+ студентов" на платформе без
реального бэкенда — взять реалистичные mock-числа, согласующиеся с
объёмом seed-данных в `tests/e2e/mocks/db.ts`).

## Критерии готовности

- Гость видит чёткий оффер и CTA без скролла (hero помещается в первый
  viewport на 1280px).
- Статистика анимированно считает при появлении в viewport, не при
  монтировании всей страницы (если hero и stats не оба видны сразу).
- FAQ-аккордеон работает клавиатурой (Tab + Enter/Space).
- Вошедший пользователь видит CTA "Мои курсы" вместо "Зарегистрироваться".

## Не входит

A/B-тестирование копирайта, видео в hero, интеграция с реальной
аналитикой посещений (Google Analytics/Plausible — отдельная задача
при явном запросе).
