# 08 — E2E Tests

Статус: [x] выполнена

## Цель

Покрыть Playwright-тестами критические пользовательские пути и подключить
их к CI, чтобы регрессии ловились до мержа.

## Ветка

`feature/08-e2e-tests`

## Шаги

1. `tests/e2e/auth.spec.ts` — регистрация → вход → выход, редирект
   неаутентифицированного пользователя с защищённого роута на /login.
2. `tests/e2e/catalog.spec.ts` — открыть каталог, применить фильтр/поиск,
   открыть карточку курса.
3. `tests/e2e/course-editor.spec.ts` — инструктор создаёт курс, добавляет
   главу/урок, меняет порядок drag & drop, содержимое сохраняется после
   перезагрузки страницы.
4. `tests/e2e/checkout-and-learning.spec.ts` — запись на (тестовый)
   бесплатный/оплаченный курс → доступ к плееру обучения → прогресс
   урока обновляется.
5. `tests/e2e/dashboard.spec.ts` — ролевой доступ: студент не видит
   instructor/admin дашборды (проверка редиректа/403-состояния).
6. Настроить тестовые фикстуры/сиды данных (моки API через
   `page.route` или тестовый бэкенд-стенд — уточнить у администратора,
   какой вариант доступен).
7. Добавить job `e2e` в `.github/workflows/ci.yml` (Playwright с
   `--reporter=html`, артефакт отчёта при падении).
8. Обновить `schedule/README.md`/этот файл отметками по мере прохождения.

## Дизайн-заметки

Не применимо — задача про тестовую инфраструктуру, не про UI.

## Критерии готовности

- Все перечисленные spec-файлы проходят локально (`yarn test:e2e`).
- CI job `e2e` зелёный на PR.
- Тесты не флейкают (минимум 3 подряд успешных прогона локально).

## Не входит

Visual regression тестирование (скриншот-диффинг) — отдельная задача при
необходимости, не блокирует эту.

## Отклонения от исходного плана (осознанные, по факту реализации)

- **Шаг 6 ("моки API через `page.route` или тестовый бэкенд-стенд —
  уточнить у администратора") решён в пользу `page.route`** —
  реального/тестового бэкенда в проекте нет и не появлялось ни в одной из
  предыдущих задач (00-06); тот же подход (моки через Playwright)
  administrator уже одобрял косвенно, принимая скриншот-QA гейты
  schedule/04-06, где `page.route` — единственный источник данных. Мок —
  `tests/e2e/mocks/{db,api,session}.ts`: `createMockDb()` даёт свежую
  in-memory "БД" на каждый тест (обязательно — `fullyParallel: true`,
  общий модульный стейт конкурентно ломал бы тесты друг другу), `db.ts`
  сидирует инструктора/админа (регистрация всегда создаёт `student` —
  форма не спрашивает роль, как и в реальном UI) и два курса (бесплатный
  + платный), `api.ts` реализует контракт `openapi.yaml` целиком (auth,
  courses, chapters, lessons, enrollments, progress, payments, analytics),
  `session.ts` — `seedSession()` сажает готовую сессию в `localStorage` в
  формате `zustand/persist`, минуя форму логина, где сам вход не предмет
  проверки.
- **Найден и исправлен баг мока, не связанный с тестами напрямую**: матчер
  `page.route('**/api/**', …)` (изначальный вариант) перехватывал не
  только реальные вызовы бэкенда, но и Vite dev-server запросы ИСХОДНИКОВ
  вида `/src/shared/api/client.ts?t=…` — там тоже есть сегмент `api` в
  пути. Перехват этих JS-модулей возвращал 404 вместо кода, из-за чего
  React ни разу не монтировался (`<div id="root">` пустой), а любой тест
  зависал на `getByLabel(...)` в таймауте. Исправлено матчером-функцией
  по `url.pathname.startsWith('/api/')` вместо glob-строки.
- **Плеер обучения — веб-компонент с закрытым shadow DOM**
  (`media-community-skin`): `element.shadowRoot` возвращает `null` даже из
  page-контекста, и `page.locator('button')`/`getByRole` внутренние кнопки
  скина не находят (проверено адресно). Старт воспроизведения в
  `checkout-and-learning.spec.ts` — через публичный `player.play()`
  напрямую на `<media-player>` (тот же метод, что дёрнул бы клик по кнопке
  play изнутри скина), с обязательными `player.muted = true` (иначе
  Chrome блокирует программный `play()` без жеста пользователя —
  autoplay policy) и ожиданием `data-can-play=true` до вызова (иначе
  vidstack бросает `"media is not ready"`).
- **Тестовое видео** — `https://www.w3schools.com/html/mov_bbb.mp4`
  (~10 сек, публичное, реально грузится в этом окружении) — тот же URL,
  что и в скриншот-гейте schedule/04 (там же зафиксирован блокирующий
  `ERR_BLOCKED_BY_ORB` на Google-сэмпле `BigBuckBunny.mp4`).
- **`checkout-and-learning.spec.ts` не проходит настоящий Stripe
  Checkout** (внешний домен вне контроля теста) — мок `POST /payments/
checkout` возвращает `checkoutUrl`, ведущий сразу на тот же
  `/checkout/:courseId?status=success&session_id=…`, как будто Stripe уже
  вернул пользователя, статус сессии сразу `completed`. Промежуточный
  поллинг (pending → completed) уже покрыт unit-тестом
  `use-checkout-status.test.tsx` — e2e проверяет итоговый доступ к
  обучению после успешной оплаты, не сам поллинг.
- **CI**: добавлена отдельная job `e2e` в `.github/workflows/ci.yml`
  (`yarn playwright install --with-deps chromium`, `yarn test:e2e
--reporter=html`, `actions/upload-artifact` с HTML-отчётом при падении,
  `retention-days: 14`) — параллельно job `build`, не блокирует её.
- Все 14 тестов (5 spec-файлов) прогнаны 3 раза подряд локально без
  падений/флейков (полный параллельный прогон, `fullyParallel: true`,
  12 воркеров, ~16 сек на прогон) — критерий готовности "не флейкают,
  минимум 3 подряд успешных прогона" выполнен.
