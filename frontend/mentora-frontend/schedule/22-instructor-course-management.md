# 22 — Управление курсами инструктора ("Мои курсы" для instructor/admin)

Статус: [x] выполнена

## Контекст

Прямой запрос администратора (2026-08-07): в текущем проекте у роли
instructor/admin нет страницы со списком СОЗДАННЫХ ими курсов —
`/my-courses` переиспользовал `MyCoursesGrid`, построенный вокруг
enrollment (записей на курс), поэтому инструктор на этом роуте видел
пустой enrollment-стейт "Вы пока не записаны ни на один курс", что
семантически неверно для его роли. Перейти к редактированию
существующего курса можно было только зная прямой URL
`/courses/edit/{id}`.

## Цель

Для instructor/admin `/my-courses` показывает сетку курсов, которые они
создали (не записи), каждая карточка ведёт в редактор курса. В header
страницы — кнопка "Создать курс". Для student — поведение не меняется
(по-прежнему `MyCoursesGrid`, записи с прогрессом).

## Ветка

`feature/22-instructor-course-management`

## Шаги

1. `openapi.yaml`: `instructorId` (query, optional) на `GET /courses` —
   переиспользует существующий листинг вместо нового эндпоинта.
   Перегенерировать.
2. Мок-бэкенд (`tests/e2e/mocks/api.ts`): фильтрация по `instructorId`.
3. `features/courses/hooks/use-instructor-courses.ts` — отдельный хук
   (не переиспользует `useCourses`, тот заточен под пагинированный
   каталог с фильтрами формы), плоский список без пагинации.
4. `features/courses/components/instructor-course-card.tsx` — карточка
   в режиме управления: превью + категория, название, цена, кнопка
   "Редактировать" → `/courses/edit/$courseId`.
5. `features/courses/components/instructor-courses-grid.tsx` — сетка +
   canonical empty-state ("Вы ещё не создали ни одного курса" + CTA).
6. `app/routes/my-courses.tsx`: роль-зависимый рендер — instructor/admin
   получают `InstructorCoursesGrid` + кнопку "Создать курс" в
   `PageHeader.actions`, student — прежний `MyCoursesGrid`.
7. Скриншот-гейт: управление курсами (с данными и пустой стейт) —
   375/768/1280px.

## Дизайн-заметки

Референс по СТРУКТУРЕ layout (сетка карточек с превью/бейджем/CTA
"Редактировать", header с кнопкой создания) — администратор указал
конкретный внешний пример при формулировке задачи; стиль/токены/цвета
полностью свои (см. `mentora-design/SKILL.md`), никаких внешних ссылок
в кодовой базе. Карточка НЕ переиспользует `CourseCard` (у той другая
семантика клика — вся карточка ведёт на публичную страницу курса;
здесь — в редактор, и вместо цены+рейтинга нужна явная кнопка действия).

## Критерии готовности

- Instructor/admin видят на `/my-courses` только свои курсы, не чужие.
- Каждая карточка/кнопка "Редактировать" ведёт в `/courses/edit/{id}`.
- Пустой список курсов → canonical empty-state с CTA "Создать курс".
- Student-поведение `/my-courses` не изменилось.

## Не входит

Удаление курса, дублирование курса, сортировка/фильтрация списка
инструктора (пока не нужна при реалистичном объёме курсов на
инструктора) — отдельные задачи при необходимости.

## Отклонения от исходного плана

- `yarn playwright test` (полный прогон) показал 9 упавших + 6 flaky
  тестов на роутах, которые эта задача не трогает (auth, checkout,
  course-editor) — совпало по времени с 8 параллельными фоновыми
  агентами (schedule/13-21), одновременно гоняющими свои dev-серверы и
  Playwright на этой же машине. Изолированный повторный прогон
  `catalog.spec.ts` + `reviews.spec.ts` (единственные тесты, реально
  затрагивающие изменённый `GET /courses`) — 5/5 зелёные. Отнесено к
  нагрузке на машину, не к регрессии этой задачи.
