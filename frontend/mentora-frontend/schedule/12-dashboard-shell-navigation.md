# 12 — Dashboard Shell (заменить Header на полноценную навигацию)

Статус: [x] выполнена

## Контекст

Администратор (2026-08-05) явно попросил: "заменить Header на
Dashboard". Найдено при подготовке задачи: сегодняшний `Header`
(`src/app/layout/header.tsx`) — это лого + имя пользователя + "Выйти"
(или "Войти"), БЕЗ единой ссылки на `/courses`, `/my-courses`,
`/dashboard` и т.д. — во всём приложении нет ни одного постоянного
навигационного элемента; переход между разделами возможен только по
прямым URL или ссылкам внутри страниц. `src/app/layout/sidebar.tsx`
существует только как TODO-заглушка с самого scaffold'а — предполагался
изначальным планом, но ни разу не понадобился ни одной задаче.

## Цель

Заменить нынешний тонкий `Header` на полноценную "оболочку дашборда" —
постоянную навигацию (sidebar на десктопе, per
`.agents/skills/mentora-design/SKILL.md` → "Responsive": "Desktop
&gt;1024px: 3 columns, fixed sidebar" — это уже задокументировано, но
никогда не реализовано), с пунктами меню, зависящими от роли
пользователя (см. также schedule/13-roles-and-collaboration.md — набор
ролей может расшириться, эта задача не должна жёстко хардкодить только
student/instructor/admin, если 13 выполняется первой/параллельно —
согласовать порядок с администратором при старте).

## Ветка

`feature/12-dashboard-shell-navigation`

## Шаги

1. Определить пункты меню по роли:
   - **Student**: Каталог, Мои курсы, Мой дашборд.
   - **Instructor**: Каталог, Мои курсы (если тоже может учиться), Мои
     курсы как преподаватель / "Создать курс" (→ `/courses/edit/new`),
     Аналитика (`/dashboard/instructor`).
   - **Admin**: всё вышеперечисленное + Аналитика платформы
     (`/dashboard/admin`), (в будущем — управление пользователями/
     курсами, вне объёма этой задачи).
   - Гость (если schedule/13 уже ввёл эту роль) — только "Каталог" +
     "Войти"/"Зарегистрироваться".
2. Реализовать `src/app/layout/sidebar.tsx` (наконец закрыть
   многолетний TODO) — фиксированный на десктопе (`lg:` breakpoint,
   ширина согласно SKILL.md), collapsible на планшете, bottom-nav или
   burger-меню на мобильном (тоже уже описано в SKILL.md →
   "Responsive", но не реализовано).
3. `RootLayout` (`src/app/layout/root-layout.tsx`) — заменить
   `<Header>` на новую композицию (sidebar + компактный top-bar с
   профилем/выходом, если по дизайну верхняя полоса всё ещё нужна для
   breadcrumbs/поиска — решить по месту).
4. Активный пункт меню подсвечен (сравнение с текущим роутом через
   `useRouterState`/`useMatch` из TanStack Router) — реализовать как
   **скользящий индикатор**, который плавно перемещается между пунктами
   при смене роута, а не мгновенную смену подсветки на разных DOM-узлах
   (паттерн и easing-токены — `.agents/skills/aaa-ui-polish/SKILL.md`,
   раздел "Активный пункт меню 'скользит'"). Это единственный
   AAA-паттерн, обязательный для этой задачи независимо от того,
   выполнена ли уже schedule/10 — см. "Дизайн-заметки" ниже.
5. Клавиатурная доступность нового меню (Tab-порядок, aria-current на
   активном пункте) — не откатывать то, что уже закрыто в schedule/07.
6. Обновить `docs/architecture/frontend-structure.md` — строка про
   `sidebar.tsx — Planned` (добавленная в schedule/07) должна стать
   "готово".

## Критерии готовности

- Из любой аутентифицированной страницы можно попасть в каждый
  доступный этой роли раздел без прямого ввода URL.
- Активная страница подсвечена в меню.
- Гостевые/неаутентифицированные пользователи не видят пунктов меню,
  требующих логина (или видят их задизейбленными с явным призывом
  войти — решить при реализации).
- Мобильная/планшетная адаптация не ломает существующие e2e-тесты
  (`tests/e2e/*.spec.ts`) — при необходимости обновить локаторы, если
  структура DOM меняется.

## Не входит

Поиск по сайту, breadcrumbs, уведомления в шапке — отдельные задачи при
необходимости.

## Отклонения от исходного плана (осознанные, по факту реализации)

- **Гостевая роль не введена** (`schedule/13-roles-and-collaboration.md`
  не выполнялась в этой пачке) — реализовано с текущими тремя ролями
  (`student`/`instructor`/`admin`) из `UserRole`, ровно как шаг 1
  описывал для этого случая. Неаутентифицированный пользователь видит
  только `TopBar` (кнопка "Войти") без sidebar/bottom-nav —
  `navItemsForRole(undefined)` возвращает пустой список.
- **"Collapsible" на планшете — адаптивное сжатие через CSS
  (`sm:w-16 lg:w-64`), без интерактивного тумблера.** С фиксированной
  шириной 640-1024px нет причины для ручного toggle-состояния — сжатая
  (только иконки) versus полная (иконка+подпись) ширина переключается
  чисто по брейкпоинту. Упрощает реализацию и устраняет целый класс
  багов (синхронизация toggle-состояния с реальным viewport). Ручной
  toggle — возможное будущее развитие, не в объёме этой задачи.
- **Реальный баг, найденный и исправленный в процессе: TanStack
  Router's `<Link>` по умолчанию сам вычисляет "активность" через
  fuzzy/prefix-матчинг** (независимо от моего собственного
  `aria-current`) и автоматически проставляет `data-status="active"` —
  из-за этого на `/courses/edit/new` ОДНОВРЕМЕННО подсвечивались и
  "Каталог" (`/courses`, как префикс), и "Создать курс"
  (`/courses/edit/new`, точное совпадение). Исправлено добавлением
  `activeOptions={{ exact: true }}` на все Link в Sidebar/MobileNav —
  своя более точная логика (`findActiveItem` в `nav-items.ts`, самый
  специфичный матч, а не первый) остаётся единственным источником
  истины для активного пункта.
- **`MobileNav` изначально был скрыт через `lg:hidden`** (правильно
  только для десктопа) вместо `sm:hidden` — из-за этого bottom-nav
  оставался виден и на планшете вместе с sidebar одновременно.
  Исправлено на `sm:hidden`.
- **Добавлен `focus-visible` ring на ссылки Sidebar/MobileNav** — не
  было в исходном тексте шага 5 явно, но требуется его же формулировкой
  ("не откатывать то, что уже закрыто в schedule/07") и отсутствовало
  при первой реализации.
- **`header.tsx` удалён** (не просто заменён по использованию) — заменён
  на `top-bar.tsx`, старый файл больше нигде не импортировался.
- **2 существующих unit-теста обновлены**
  (`tests/components/features/analytics/dashboard-routes.test.tsx`) —
  `getByText('Аналитика платформы')` стал неоднозначным: тот же текст
  теперь дублируется в пункте меню Sidebar (виден только `admin`) И в
  `<h1>` страницы. Переведено на `getByRole('heading', ...)` для
  однозначности — предвиденный в критериях готовности случай
  ("обновить локаторы, если структура DOM меняется").
- Скриншот-гейт — 4 сценария (каталог/студент, дашборд/инструктор,
  дашборд/админ, "Мои курсы"/студент) × 375/768/1280px = 12 файлов в
  `docs/qa-screenshots/schedule-12-dashboard-shell-navigation/` —
  показывают все 3 роли и оба брейкпоинт-состояния sidebar
  (icon-only/полный) и bottom-nav.
